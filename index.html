Classic ASP API를 Spring으로 전환

2022.12 ~ 2024.03 · 부동산114

제휴사들이 쓰던 부동산 정보 API를 옮겼습니다.

  • 문제Classic ASP API에 로직이 여기저기 흩어져 있음
  • 한 일Spring REST API로 다시 설계하고 옛 API와 나란히 운영
  • 결과제휴사는 코드를 하나도 고치지 않고 넘어옴
  • Classic ASP
  • Spring
  • MyBatis
  • Swagger
전 · Classic ASPcomplex.asp
<%
code = Request("code")
Set conn = Server.CreateObject("ADODB.Connection")
conn.Open Application("DSN")
Set rs = conn.Execute( _
  "EXEC usp_단지정보_S '" & code & "'")  ' SQL을 문자열로 이어 붙임
If Not rs.EOF Then
  Response.Write "{""name"":""" & rs("단지명") & _
    """,""addr"":""" & rs("주소") & """}"  ' JSON도 손으로
End If
rs.Close : conn.Close   ' 오류가 나면 연결이 남음
%>
후 · Spring BootComplexController.java · ComplexMapper.xml
@Tag(name = "단지")
@RestController
@RequiredArgsConstructor
@RequestMapping("/v1/complexes")
public class ComplexController {
  private final ComplexService complexService;

  @Operation(summary = "단지 정보 조회")
  @GetMapping("/{code}")
  public ApiResponse<ComplexDto> get(
      @PathVariable @Pattern(regexp = "\\d{10}") String code) {
    return ApiResponse.ok(complexService.find(code));  // 없으면 404
  }
}

<!-- ComplexMapper.xml : 프로시저는 그대로, 값은 바인딩 -->
<select id="findByCode" resultType="ComplexDto">
  EXEC usp_단지정보_S #{code}
</select>

예시 코드같은 프로시저를 쓰면서 입력 검사, 공통 응답 형식, Swagger 문서를 붙였습니다. 실제 회사 코드가 아니라 구조를 보여 주려고 다시 쓴 것입니다.

AI로 일하는 방식

Claude Code에 일의 종류마다 맞는 스킬을 붙여 씁니다. AI가 만든 결과는 그대로 믿지 않고 마지막엔 직접 확인합니다.

  • 화면은 디자인 스킬로만들기 전에 impeccable design-taste-frontend로 방향을 잡고, 다 만든 뒤에는 interface-review 같은 검토 스킬로 정렬과 글자를 다시 봅니다.
  • 복잡한 수정은 설계부터여러 파일을 건드리거나 원인을 모르는 버그는 pstack 흐름으로 구조를 먼저 잡고, 테스트로 확인하며 고칩니다.
  • 글은 humanize 스킬로화면 문구와 문서는 오픈소스 im-not-ai의 humanize 스킬로 번역투와 AI 티를 걷어 냅니다. 이 포트폴리오의 프로젝트 제목도 이렇게 다듬었습니다.
  • 규칙과 실수는 메모로SQL 작성법, 커밋 규칙, 한 번 했던 실수를 프로젝트 메모 200여 개로 쌓아 다음 작업에서 자동으로 불러옵니다. 같은 실수를 두 번 하지 않게 합니다.
  • 찍어 보고 끝내기화면을 고치면 폰과 PC 크기로 직접 찍어 확인합니다. 글자 수나 응답 코드만 보고 됐다고 하지 않습니다.
  • 커밋은 사람이 확인한 뒤에AI가 고친 코드는 로컬에서 직접 돌려 보고, 확인한 것만 커밋하고 배포합니다.
